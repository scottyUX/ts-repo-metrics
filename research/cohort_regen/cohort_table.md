**1. Halstead operands (known).** The Python path still collapses every string
literal to one atom and every numeric literal to one atom — precisely the defect
D7 fixed for TS/JS. Left in place on purpose: escomplex, the baseline
`research/validation` measures against, is JavaScript-only, so a Python change
could not be validated. This is why Halstead/MI above are TS/JS-scoped.

**2. Cognitive complexity (newly established this pass).** Python cognitive
complexity is **also unvalidated, and additionally appears incorrect**. The
validation corpus contains **0 Python functions out of 4,645**, so no Python
cognitive score has ever been checked against any baseline, under either the old
rule or the D4 replacement. The D4 port is gated to ECMAScript, so Python still
runs the pre-D4 code path — and Python's `elif_clause` is a *sibling* of the
`if`, listed in `PYTHON_COGNITIVE_CONTROL`, so each `elif` takes a nesting
increment it should not.

Measured by [`../validation/python_cognitive_probe.mjs`](../validation/python_cognitive_probe.mjs)
on structurally identical snippets:

| shape | Sonar spec | TS/JS (validated) | Python |
|---|---|---|---|
| `if / elif / else` (flat) | 3 | 3 ✓ | **4** (+1) |
| `if / elif ×3 / else` (flat) | 5 | 5 ✓ | **8** (+3) |
| chain nested 1 level inside an `if` | 5 | 5 ✓ | **7** (+2) |
| `if / else { if }` | 4 | 4 ✓ | **3** (−1) |
| bare `if / else` | 2 | 2 ✓ | 2 ✓ |

Python disagrees with the spec on **4 of 5 shapes**, in both directions. Worse
than the old JS defect: it over-counts even *flat* `elif` chains, and the error
grows with chain length (+3 on a four-link chain) — the escalation behaviour D3
removed for JS. Cohort means are consistent with inflation: **Python mean
cognitive 2.00 vs TS/JS 1.11.**

**No code was changed** — this was an investigation, per instruction.
**Recommendation: scope cognitive complexity to TS/JS as well**, on the same
grounds as Halstead. Cognitive figures in this document's `avgComplexity` column
are cyclomatic, not cognitive, and are unaffected.
